# security-module-detailkonzept

Das Detailkonzept für die Module des Bereichs Security. Es wendet
`../../../1_grundkonzepte/modul.md` an und ergänzt es um das, was bei Security
gilt und bei anderen Bereichen nicht.

| Datei | Inhalt |
|---|---|
| `security-modul.md` | die vier Zusatzangaben, die Ausfüllhinweise zu den Feldern aus Ebene 1, die Schnittregeln für Security, die Prüfliste |
| `rechtsrahmen.md` | Normen, Auslöseschwellen, Fristen, externe Zustimmungen, Mitwirkende ohne Weisungsverhältnis — die Belegstellen, auf die Module verweisen, statt sie zu wiederholen |
| `bemessungsverfahren.md` | die Verfahren, nach denen bemessen wird, je mit Quelle und Verbindlichkeitsstufe. Die Zahl steht im Modul, nicht hier |

## Was hier nicht steht

**Keine ausgefüllten Module.** Die liegen in
`../../../3_instanzen/module/security-module-instanzen/`.

**Keine Modullandkarte.** Eine Liste der vorhandenen Module ist ein Register von
Instanzen und gehört neben die Instanzen. Sie liegt in
`../../../3_instanzen/module/security-module-instanzen/modullandkarte.md`.

**Keine zweite Feldliste.** Welche Felder ein Modul hat, steuert die Modulart,
nicht der Bereich. Dieses Detailkonzept ergänzt Felder; es benennt keines um,
lässt keines weg und lässt keines anders bedeuten.

**Keine Wahlpflichtgruppen als eigene Datei.** `modul.md` legt Entscheider,
Frist und Alternativen in die Felder des Grundmoduls, damit sie genau einmal
stehen. Eine eigene Datei wäre die zweite Stelle.

**Keine Übergabekarte als eigene Datei.** Übergaben sind ein Feld je Modul. Was
bereichsweit gilt, ist die Regel für Übergaben an Stellen ohne
Weisungsverhältnis; sie steht in `security-modul.md`.

## Zum Bereich

Owner ist AL Logistik + Security — im Playbook V1.0 ist Security keine eigene
Organisationseinheit, sondern mit Logistik zusammengefasst. Die Ladehof- und
Zufahrtsthemen liegen deshalb an einer bereichsinternen Grenze.

Diese README ersetzt einen Platzhalter, der fünf Dateien vorsah. Die Begründung
je gestrichener Datei steht oben.
